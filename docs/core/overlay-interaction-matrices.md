# Overlay Interaction Matrices

## Purpose

This page records the current evidence for the public overlay derivatives that trail Dialog maturity. The matrices are intentionally conservative: a behavior can be implemented and still remain below beta/stable until it has browser and manual assistive-technology evidence.

Evidence levels:

- `Covered`: direct Core test coverage exists.
- `Inherited`: shared overlay, portal, presence, or floating kernel coverage exists, but the primitive has only thin direct coverage.
- `Documented gap`: product policy is known, but evidence is not strong enough for a maturity claim.

## Popover

Current maturity: `experimental`.

Popover is a disclosure-style overlay with interactive `role="dialog"` content. It is non-modal by default and uses the shared overlay layer, presence, portal, and Floating UI adapter.

| Behavior                               | Current evidence                                                                                                                      | Notes                                                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trigger opens and toggles content      | Covered by `packages/core/src/popover/popover.test.tsx` and `packages/core/test/overlay-vertical.behavior.test.tsx`.                  | Trigger exposes `aria-haspopup="dialog"`, `aria-expanded`, and `aria-controls`.                                                                           |
| Controlled and uncontrolled open state | Inherited from `createOverlayController` controllable state coverage.                                                                 | Popover uses `open`, `defaultOpen`, and `onOpenChange`; direct controlled Popover edge tests are still useful before beta.                                |
| Focus entry on open                    | Covered by `packages/core/src/popover/popover.test.tsx`.                                                                              | Opening focuses the first tabbable element in content, or content itself when no tabbable child exists.                                                   |
| Focus restoration on close             | Covered by `packages/core/src/popover/popover.test.tsx`.                                                                              | Escape close restores focus to the previously focused trigger through the overlay focus lifecycle.                                                        |
| Escape dismissal                       | Covered by `packages/core/src/popover/popover.test.tsx`.                                                                              | `onEscapeKeyDown` can prevent dismissal.                                                                                                                  |
| Pointer/focus outside dismissal        | Covered by `packages/core/src/popover/popover.test.tsx` and `packages/core/test/overlay-vertical.behavior.test.tsx`.                  | `onPointerDownOutside`, `onFocusOutside`, and `onInteractOutside` can prevent dismissal.                                                                  |
| Trigger as an inside target            | Inherited from Popover's `containsTrigger` overlay option.                                                                            | Clicking/focusing the trigger should not count as outside interaction. Keep direct regression coverage if nested trigger policies change.                 |
| Portal rendering and custom mount      | Covered by `packages/core/src/popover/popover.test.tsx`.                                                                              | `Popover.Portal` delegates to public `Portal` with optional `mount`.                                                                                      |
| `forceMount` and presence retention    | Covered by `packages/core/src/popover/popover.test.tsx`.                                                                              | Force-mounted content remains in the portal host with `hidden` and closed state metadata. Transition timing remains kernel-level evidence.                |
| Floating geometry and CSS variables    | Covered by `packages/core/test/overlay-vertical.behavior.test.tsx`; arrow is covered by `packages/core/src/popover/popover.test.tsx`. | Geometry delegates to Floating UI. More browser layout evidence is needed for scroll containers and viewport edges.                                       |
| Modal mode                             | Inherited from shared overlay layer behavior.                                                                                         | `modal` blocks outside pointer events and participates in outside hiding through the kernel, but Popover-specific browser and AT evidence is still a gap. |
| Nested overlay behavior                | Documented gap.                                                                                                                       | Dialog has stronger nested overlay proof than Popover. Popover/Menu/Tooltip combinations still need browser tests.                                        |
| Manual assistive-technology behavior   | Documented gap.                                                                                                                       | Do not claim stable dialog announcement behavior until manual AT notes exist.                                                                             |

Popover beta path: add browser matrix coverage for non-modal and modal Popover, nested overlay combinations, scroll/collision geometry, and manual AT notes for trigger/content announcement.

## Tooltip

Current maturity: `experimental`.

Tooltip is a non-interactive description surface. It uses `role="tooltip"` content and wires the trigger with `aria-describedby`. It should not be treated as a general interactive hover card or popover.

| Behavior                                 | Current evidence                                                                                                                                                              | Notes                                                                                                                                                                                                              |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Pointer hover opens content              | Covered by `packages/core/src/tooltip/tooltip.test.tsx` and `packages/core/test/overlay-vertical.behavior.test.tsx`.                                                          | Touch pointer enter is ignored; no long-press touch tooltip policy is claimed.                                                                                                                                     |
| Focus opens content                      | Covered by `packages/core/test/overlay-vertical.behavior.test.tsx`.                                                                                                           | Focus uses the same delay scheduling path as pointer intent.                                                                                                                                                       |
| Pointer leave and blur close content     | Covered for pointer leave in Tooltip tests and overlay vertical; blur behavior is implemented through the same interaction policy and should get direct coverage before beta. | Close can be delayed with `closeDelay`.                                                                                                                                                                            |
| Provider delay and skip-delay group      | Covered by `packages/core/src/tooltip/tooltip.test.tsx`.                                                                                                                      | Provider values can be overridden at Root level. Current tests prove open delay and recent-close skip delay.                                                                                                       |
| Hoverable content and pointer grace area | Covered by `packages/core/src/tooltip/tooltip.test.tsx`.                                                                                                                      | This keeps the tooltip open while the pointer moves through a grace polygon. Tooltip content should still remain non-interactive for accessibility claims.                                                         |
| Escape dismissal                         | Covered by `packages/core/src/tooltip/tooltip.test.tsx` and `packages/core/test/overlay-vertical.behavior.test.tsx`.                                                          | Escape closes from trigger or content.                                                                                                                                                                             |
| `aria-describedby` relationship          | Covered by `packages/core/test/overlay-vertical.behavior.test.tsx`.                                                                                                           | Trigger currently carries `aria-describedby` for the generated content id. Announcement timing remains a manual AT evidence gap.                                                                                   |
| Portal rendering                         | Inherited from `Portal` and covered through Tooltip vertical mounting.                                                                                                        | Custom mount and force-mount behavior should get direct Tooltip coverage before beta.                                                                                                                              |
| Floating geometry and arrow              | Inherited from the shared Floating UI adapter and arrow helper.                                                                                                               | Tooltip-specific collision/arrow browser evidence remains open.                                                                                                                                                    |
| Disabled trigger guidance                | Documented gap.                                                                                                                                                               | Native disabled buttons do not receive focus or pointer events consistently. Wrap disabled controls in an enabled element when a tooltip is necessary, and keep the disabled control itself semantically disabled. |
| Hoverable content policy                 | Documented limitation.                                                                                                                                                        | The implementation supports hoverable content for pointer continuity, but interactive tooltip content is not a stable accessibility claim; use Popover or HoverCard for interactive content.                       |
| Manual assistive-technology behavior     | Documented gap.                                                                                                                                                               | Do not stabilize Tooltip until `aria-describedby` timing and common screen-reader behavior are manually checked.                                                                                                   |

Tooltip beta path: add direct tests for blur close, close delay, force-mounted portal content, disabled-trigger examples, and browser/manual AT notes for hover, focus, Escape, and announcement timing.
